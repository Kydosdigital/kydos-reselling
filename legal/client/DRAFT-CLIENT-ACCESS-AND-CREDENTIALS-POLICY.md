# DRAFT Client Access and Credentials Policy

## 1. Principle

Use delegated, role-based access whenever a platform supports it.

Examples:

- Meta Business access
- Google Ads user access
- Analytics permissions
- LinkedIn Page roles
- CMS users

## 2. Do not share unnecessarily

The Agency should not ask for:

- online banking password
- primary personal email password
- MFA code except transiently as part of a secure owner-led login where absolutely necessary
- Companies House personal code
- full payment-card details

## 3. Password manager

Where a credential must be shared, use the Agency's approved password manager/secure sharing method.

Do not use a general Google Doc as the recommended password vault.

## 4. Staff access

Grant only what the staff member needs.

Account Manager:
assigned clients only where possible.

Creative:
assets/files required for production.

Operations Manager:
broader oversight.

## 5. Recording access

Maintain an Access Register containing:

- system
- owner
- Agency access level
- staff users
- date granted
- date removed

Do not record the password itself in the register.

## 6. Security incidents

If credentials are compromised:

1. change/revoke
2. sign out active sessions where possible
3. enable/reset MFA
4. assess data risk
5. document incident
6. notify Client
7. follow data-breach process where applicable

## 7. Offboarding

At service end:

- remove Agency users
- transfer required ownership
- revoke staff access
- confirm sensitive credentials no longer stored
