# Programme Portal Admin Operations SOP

## Purpose

Run the programme consistently across multiple participants.

## New participant

After payment:

1. verify payment
2. verify agreement/consents
3. create participant record
4. apply tier
5. set start date
6. calculate support end date
7. provide portal access
8. send intake
9. assign programme owner
10. create implementation board where required

## Tier access

Use the Tier Access Matrix.

Do not manually guess which participant should see which implementation services.

## Participant record

Maintain:

- legal name
- contact details
- tier
- payment
- agreement version
- programme start
- support end
- launch target
- implementation owner
- status
- professional referrals
- major decisions

Avoid unnecessary sensitive information.

## Weekly admin

Review:

- new participants
- incomplete intake
- overdue participant actions
- support end dates
- Build/DFY blockers
- professional referrals
- handovers approaching
- complaints/escalations

## Content updates

When a programme document changes:

1. update repository source
2. record version/date
3. decide whether update is:
   - minor
   - important
   - legal/compliance critical
4. update portal
5. notify active participants where material
6. regenerate downloadable files where needed

## DRAFT documents

Do not remove DRAFT status until the review register records professional approval.

## Support end

7 days before:

send reminder.

On end date:

- update support status
- retain portal access according to agreement
- offer paid extended support if appropriate

## Participant completion

When launch-ready:

- mark Live
- complete launch review
- confirm ongoing owner responsibilities
- ensure finance/operations routines are active

For Done For You:

- formal handover
- begin 90-day handover support
