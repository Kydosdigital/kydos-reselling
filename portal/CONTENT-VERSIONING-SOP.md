# Programme Content Versioning SOP

The GitHub repository is the source of truth.

## Why versioning matters

The programme contains:

- pricing
- operating procedures
- tax reference points
- Companies House rules
- data-protection guidance
- immigration-readiness guidance
- contracts/policies
- platform workflows

Some of these change.

## Version fields

For important documents record:

- version
- last reviewed date
- owner
- review type

## Change types

### Minor

Examples:

- typo
- clearer explanation
- formatting

No participant announcement normally required.

### Operational

Examples:

- new onboarding step
- changed team deadline
- new CRM workflow

Notify relevant active team/participants if it changes what they need to do.

### Commercial

Examples:

- package price
- tier inclusion
- support period

Do not silently change the contract for an existing paid participant.

### Legal/compliance critical

Examples:

- statutory threshold
- Home Office requirement
- consumer cancellation wording
- data-protection rule

Update promptly.

Use professional review where required.

## Generated files

Whenever approved source changes materially:

1. update Markdown
2. regenerate Word
3. regenerate PDF
4. regenerate spreadsheet if affected
5. replace portal download
6. archive old version where needed

## Old versions

Keep enough history to understand:

- what a participant agreed to
- which policy version applied
- what changed

Do not overwrite executed contracts.
